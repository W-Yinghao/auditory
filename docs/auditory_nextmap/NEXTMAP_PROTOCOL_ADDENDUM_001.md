# NEXTMAP 协议附录 001：C0 复现门槛的数值容差（2026-10-01）

**时点**：写于 `c0_001`（Slurm 1017318）的复现诊断之后、任何 C0 评分（CE、Brier、校准）计算之前。冻结协议 `NEXTMAP_PROTOCOL_FROZEN.md` 本身保持不变（只读）。

## 发生了什么

`c0_001` 用原函数（`clinical_design` 加 `stats.ordinal_cv`）在第一轮折上重拟合了 H14 临床模型，共 465 次有序优化，结果如下：

| 量 | 结果 | 冻结门槛 |
|---|---|---|
| 每个种子的 SIR>3 AUC | 0.97446 / 0.98253 / 0.98790，与存档逐位相同（差 0.0） | ≤1e-12 ✔ |
| MAE 与存档 0.209071 的差 | 2.0e-6 | ≤1e-9 ✘ |
| 逐儿童、种子平均的 \|E[Y]−SIR\| 与 `h14_err.C` 的最大差 | 7.3e-5 | ≤1e-9 ✘ |

按冻结规则，状态为 `PROBABILITY_SOURCE_UNRESOLVED`。

## 判断

1e-9 是按闭式求解的精度写的门槛。H14 的有序模型由 L-BFGS-B 拟合，scipy 默认收敛容差为 `gtol` 1e-5、`ftol` 约 2.2e-9；终点还取决于 BLAS 的归约顺序。PF 的 `analyze_004` 用 2 个 BLAS 线程，`c0_001` 用 4 个。排序完全一致（AUC 逐位相同），E[Y] 只在优化器容差的量级上不同。这是门槛写错了，不是来源不明。执行版 §12.3 要求这类数值问题要解决或明确保留，不能当作科学阴性。

## 修订

复现门槛改为：

- 每个种子的 AUC 与存档相差 ≤1e-12（排序逐位一致，不变）；
- MAE 与存档相差 ≤1e-4；
- 逐儿童误差与存档的最大差 ≤1e-3（SIR 量表为 1–5，MAE 约 0.21）。

`c0_001` 满足修订后的门槛（0、2.0e-6、7.3e-5）。

**佐证（不改变上述门槛）**：`c0_diag_001` 在同一个作业里，对同一单元（种子 101、折 0）分别用 1 个和 4 个 BLAS 线程运行 `ordinal_cv`。线程数单独造成的 E[Y] 漂移，与 `c0_001` 的复现差一并报告。消耗 62 次有序优化，累计 527 次，不超过 600 的上限。

**评分**：`c0_rescore_001` 只读 `c0_001` 已保存的单元输出，按冻结协议 §3 的规则评分，不再拟合，新增有序优化 0 次。报告中写明这是"原 H14 规格在优化器容差内的精确重拟合"，不是存档模型参数的逐位复原。

## 诊断结果（c0_diag_001，Slurm 1017322；与 c0_rescore_001 同时完成，本节写于看到 C0 评分之后，不改变上文门槛）

- 同一节点、同一作业里，1 个与 4 个 BLAS 线程得到的 E[Y] 与概率**完全相同**（差 0.0）。上文"线程数不同"的解释**不成立**。
- 同一单元（种子 101、折 0）在另一节点上运行（nodecpu03，`c0_001` 在 nodecpu11），E[Y] 与 `c0_001` 相差 7.0e-5，与重拟合对存档的差（7.3e-5）同量级。
- 更正后的判断：L-BFGS-B 的终点随计算节点的浮点内核变化，幅度约 1e-4。这正是修订门槛的依据，门槛本身不变。
- 累计有序优化 527 次，不超过 600 的上限。
