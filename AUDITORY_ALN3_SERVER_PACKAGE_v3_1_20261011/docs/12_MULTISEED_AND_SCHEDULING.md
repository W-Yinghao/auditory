# 12 · 多seed、去重与实际排程决定

## 1. 结论

**仍需要多seed，但不继续给即将被替代的每个旧FM配置补满seed。**

保留“一个seed广覆盖 + 成对主比较三个seed”。广覆盖seed3401；登记主面板使用3401、3407、3413。三seed是本轮工程计划，不是样本充足证明，也不是停止追加复核的统计定律。

已有seed对应真实训练随机性；对同一个checkpoint换bootstrap种子不算新的训练seed。反之，纯确定性线性探针不需要为了凑三seed重复完全相同运算；它随源checkpoint seed或真实采样变化评价。

## 2. 针对server当前账目的操作

### item-2小编码器

完成这一轮已经登记并在运行的多seed比较；其结构仍是ALN3主基线。保留有效结果，完成后优先复用，不再自动开启另一次全矩阵重复。若仍有未启动旧单元，与ALN3拥有完全相同训练合同的先去重；只因名称相同不算兼容。

不为新包中断接近完成的有效小模型。若无上游依赖的新ALN3任务已就绪，队列均衡安排，不必等全部item-2结束才提交新作业。

### item-2基础模型旧粗时间接口

将尚未开始的全矩阵补seed置于可恢复backlog；已运行的可到下一个安全checkpoint后让出新任务所需资源，接近完成且无需阻塞新任务的可以结束。此处“旧粗时间接口”指已修复空间平均但仍每秒一行的合法ALN2配置，**不是全部无效数据**。

旧面板中已完成的三seed直接保留；核心对照若仍缺少某个seed，只定点补齐。真正的旧channel-mean错误分支继续仅作历史，不为它补新的主实验或给下游提供teacher。

理由是重复性与当前主线价值，不是根据某个seed负值做选择。保存所有旧行、进度、checkpoint和回退方式，不删除backlog。

### item-3

3a短probe结束且工程接口正确后即可跑，使用现有checkpoint。低预测成绩不阻止3a完整评价，不阻止A/E。

3b/3c并入B：在`governance/item3_mapping.json`绑定旧登记与新配置；新配方、dense目标与旧配方分开标记。不是通过改名取消原问题，也不是再额外跑400次重叠训练。

## 3. 新ALN3主面板按“差值”登记

`configs/seed_confirmation_pairs.yaml`列出比较角色，不要求对全部5996条乘三。先将逻辑角色绑定到实际config/target/split hash；按此前授权无需再次征求作者同意。角色绑定不能看新seed结果或临床显著性。

| 面板 | 比较的核心 | seed必须覆盖的对照 |
|---|---|---|
| P1 局部方法 | lag-local相对legacy/density；NCE相对传统CS | 在同target同完整窗下，各方法均有匹配seed；主早晚比较覆盖两窗及联合 |
| P2 预训练与dense读出 | dense相对phase-linear；同架构pretrained-full相对random-full；冻结/PEFT的实用配方 | 输入、target、适配一致时才能隔离读出；pretrained-PEFT−random-full不是纯初始化效应 |
| P3 局部与FM互补 | local-only、简单拼接、预训练残差、随机分支与容量对照 | 局部base与残差完整依赖；不能只重跑残差头而遗漏base随机性 |
| P4 注意与适配 | 强局部表示的对齐/选择/联合；无适配相对空间适配 | 同时刻候选、相同query，source模型/个人支持规则一致 |
| P5 私有贡献 | GX原生、局部NCE/CS、匹配随机/通用预训练、公共先验迁移 | 原生与探针并报；迁移比较记录donor的随机性；不只重复最高AUC的配置 |

冻结/PEFT/部分/full全部保留广覆盖完整训练；核心面板选法由预先登记的比较需要决定，不要求所有超参数全三seed。默认紧凑面板在局部/私有目标比较保留NCE与传统CS，在基础模型读出、时间扩展和注意任务上先固定NCE共同目标，避免每条重复轴再乘所有loss；CS仍完成广覆盖，若最终声称CS特定的FM/时间收益，再对该成对比较补同seed。C的纯初始化对照采用pretrained-full与random-trainable匹配更新方式，PEFT与random-full的差只称配方比较。现有ALN3已提交的有效面板不因为新登记较小就砍掉；尚未提交而不再属于核心的行标`deferred_redundant`，保留原因。

本包给出配对角色而不编造server实际config hash。最终新增作业数由兼容性匹配与已完成记录决定；不承诺固定新拟合总数。

## 4. 哪些必须重跑整条链，哪些可以复用

- 同一local seed供多个融合方法共享是合理的：在同seed内形成更干净的配对。不同seed应有各自base，或者明确将结论限定为固定base上的head随机性。
- 完整pipeline稳定性包括donor/base、teacher选择、任务头、采样、优化。若某个昂贵donor固定，只能写“以此donor为条件的三seed”，不能称全部迁移链稳定。
- 为尽快运行，允许先做固定donor的广覆盖。至少对最终主要迁移比较补全预先登记的pipeline seed链，结果好坏均报告。
- 同训练合同已完成：复用。只改metadata/统计：重汇总。只改校准/探针：evaluation/probe拟合。target/head/训练配方改变：新训练版本。
- 一张表使用三seed均值，一张使用3401，必须标清；不能把不同seed策略混写成所有结果均三seed。

## 5. 推断与报告

同一测试参与者的多个内容折、seed、访视不构成更多独立人。先形成每seed每人的量及同人方法差。报告每seed差值、均值、范围/标准差；参与者bootstrap按身份整体重抽所有seed向量，区间注明条件于这些训练。

三个seed对训练随机性的刻画仍粗，不能用极窄的参与者区间代替完整训练不确定性。种子稳定不解决年龄/设备效应的独立人数问题，也不使旧数据变成新的独立确认队列。

所有主要方法差均给基线和候选的相同seed集合。不同方法缺seed时先报共同集合与缺失状态，不静默用各自最佳seed。支持不足的结果完整报告，不以再次跑seed“直到显著”。

## 6. 实际优先级（保持总10-GPU授权）

1. 解除就绪任务阻塞的短probe/短推理；
2. 已就绪ALN3主训练及其必需base/donor，与在跑有效小模型并行；
3. 本轮核心配对seed面板与依赖已就绪的C/D/E；
4. 从完成checkpoint开展的科学评价；
5. 旧FM重复面板、可选资源新训练仅使用不会阻塞上列的资源。

CPU汇总/数据目录核实与GPU训练并行；大型特征导出限制I/O，不把CPU或存储打满。10-GPU是该研究者授权任务的**合计上限**，不是每个实验族各10张。只管理本项目自己的明确job IDs，不触碰集群其他用户任务。

别为做一份完美队列报告阻塞开跑。下一次状态报告给出实际已提交IDs、running/pending/completed、依赖解除、复用/暂缓数、GPU使用与运行时估计；不是再交一份计划然后询问是否启动。
