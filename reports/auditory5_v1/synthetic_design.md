# Synthetic validation design (corrected v2, before real model outcomes)

The initial unexecuted design was rejected during review and its failing development test log is retained as contracts_006. B had incorrectly used identity as the target, E's positive/negative gap definition was reversed, and A's negative world incorrectly retained a stable condition contrast. The corrected mechanisms use binary history, a source-dropped target direction as the positive transfer-gap world, and class-independent backgrounds that cancel from A's contrast.

Each route and sign runs exactly 100 worlds over a fixed SNR grid (0.25, 0.5, 1, 2) and sample-size grid (32, 48). One world has independent training and test identities. D uses twice this number of candidate observations. The simulation bootstrap uses 400 resamples for computational economy, whereas real-data intervals retain the plan's 2000. Detection requires an effect floor and a positive bootstrap lower endpoint; negative-world detection is an estimated false-screen rate with Wilson Monte Carlo intervals, not a formal p-value. Failed worlds and convergence warnings remain visible. Low power or excess false screens are reported, not tuned away.

A uses training-only contrast PCA and the production distinct-identity matching bootstrap. B compares a spline context baseline with post EEG and separately controls pre EEG. C uses fixed 32-unit MLPs, both single views, duplicate controls and a linear XOR comparator. D uses the production class-centered head geometry, verifies probability invariance, fits a training-only 3D null PCA, and selects ridge penalties by training-only folds with clinical covariates. E compares target heads on exactly the same target training/test samples; its negative representation is an invertible rotation. Classification losses use production candidate/class-balanced bits.

These worlds exercise estimators and known mechanisms. They do not replace full encoder-training isolation tests, real input integration checks, all prespecified sensitivity analyses, or genuine held-out clinical evaluation. Completion PASS means code ran without support/numerical failures; it does not by itself certify acceptable error rates or any scientific route.
